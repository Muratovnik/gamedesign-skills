# Paired model tasks: outcomes and evidence boundary

Twelve fresh subjects completed six task families, once per version. The
candidate used all four changed operations successfully, and both versions
completed the two small paper controls without requiring an engine, package
installation, simulation or participant session. These results support usable
operational additions. They do not establish general superiority over main.

The complete original report, frozen tasks/rubrics, outputs, operation logs and
evaluator corrections are retained in [behavior-evidence.zip](behavior-evidence.zip).
Start with `REPORT.md` and `model-runs/run-index.json` after extraction. The
[archive manifest](behavior-evidence-manifest.json) identifies all 243 entries:
235 unchanged original evidence files, their unchanged source manifest, an
archive index and six license/attribution files. Every entry was reopened and
its SHA-256 checked. The archive contains no installed dependency bundle.

### What the calculations and native consumers actually establish

For the original matrix, both versions obtain row mixture
`(15/44, 17/44, 3/11)`, column mixture `(7/22, 17/44, 13/44)` and value `53/44`.
For the one-cell patch, the mixtures are `(3/10, 2/5, 3/10)` and
`(7/20, 9/20, 1/5)`, with value `13/10`. The increase is `21/220`, and every
action remains in support. Independent Fraction calculations recover the same
lower and upper response bounds with zero gap. Main's successful implementation
is counterevidence to any claim that the new helper was necessary.

Both observation handoffs retain all 22 notes, six sessions, five participant
IDs and 14 attempts. Both distinguish the current build's 12 attempts, nine
clears and three hits from the old build's two clears; repeated participants,
author knowledge, assisted success and the reduced-motion case remain visible.
Both identify the timing conflict: input remains locked through tick 74, while
clearance needs acceptance by tick 70. Neither turns this synthetic exercise
into a claim about collected human evidence.

Main's structured `none` category explicitly means no current help was reported,
and its note-level qualifications are retained. Its readable table nevertheless
says both old-build successes occurred without help, although N18 does not say
that. This loss of qualification is the bounded defect. Candidate explicitly
keeps N18 and N06 assistance unknown. Candidate also invokes the real importer
with `--csv`, `--manifest` and `--output`; reopening the saved report confirms
`conditions`, `collection_method` and `units` equal the manifest. The importer
does not generate the separately authored narrative report or certify the notes.

Both Ink artifacts save after the only token is spent and a permit is received,
with two choices still pending. Separate-process direct-runtime replay loads
the delivered native state into a fresh Story, preserves the variables and
pending choices, and reaches the shared ferry scene without replaying payment.
Both execute the keep-token/no-permit and quiet routes too. Both first encounter
an unexported package metadata subpath; main additionally corrects a Compiler
configuration requiring a FileHandler. These failures remain in the record and
are not misreported as final story failures.

Both glTF outputs change only the POSITION accessor count from four to three.
The corrected JSON files are byte-identical, and the 42-byte binary is unchanged.
The real Khronos consumer reads the external buffer. It returns
`ACCESSOR_TOO_LONG` for the original and zero final errors, warnings, infos and
hints for the correction. This establishes the represented format checks and
preservation; it does not establish engine import, visual fidelity or readability.

### Neighboring legitimate outcomes

Main's paper exchange maintains the positive invariant `2c + 3s = 6`.
Candidate's `c + s` never increases above the initial three tokens. Both show
the original repeatable 3-to-4 copper gain and change just one exchange rate.
The task permits both a lossless round trip and a lossy one.

The expressive scenes preserve ambiguity about the clerk, offer three actions
with distinct local responses and physical traces, and converge on the same
departure. Both are finished playable prose. Neither adds Ink, a score, a win
condition or a playtest as a prerequisite. The judgment concerns the actual
composition; it is not a measured emotional response.

## Preserved limitations and corrections

Both matrix arms ran under the same real SciPy/NumPy versions, but the initial
Python alias selected the base prefix. Candidate's optional Markdown parser
check encountered a missing package. Mathematics was independently verified,
and that harness failure is excluded from product-efficiency claims. Before
dependency-sensitive observation checks, the shared Python launcher was repaired
for both arms. The exact repair timing and versions are recorded.

A shared outer heredoc marker also collided with a report reproduction example
in both matrix arms. Both reports were repaired and reopened. The not-yet-started
families 03–06 received the same corrected logger instruction. Failed commands,
the first-pass observation grading and the correction of an evaluator's mistaken
description of the importer interface remain in the archive. No task was rerun
to obtain a preferred winner.

All task inputs and frozen runtime source files retain their hashes. One
candidate observation import generated a bytecode cache in its task-local skill
copy; that incidental file is recorded. Recorded commands show no reads of the
grader key, another subject workspace or credentials. The shared filesystem was
not an enforced isolation boundary, and the logger is neither a native full
conversation trace nor a syscall trace. Unlogged outer actions cannot be ruled
out by source equality alone.

The sample has one draw per arm per family, no production weighting and an
unblinded outcome grader. It supports these concrete outcomes and operation
uses; it cannot estimate stochastic reliability, causal benefit of individual
instructions, broad quality, or portability across clients and models.

skills and 18 ambient skills. Ordinary authenticated model attempts produced no
completed turn: retained attempts were interrupted before events, and bounded
preflights timed out. An additional explicit prompt through an owned terminal

The original attempts are in the main evidence archive; the independent terminal
preflight and redacted Claude status are in
[native-model-preflight.zip](native-model-preflight.zip) and its
[manifest](native-model-preflight-manifest.json). No credential content is
included. No credentials, network restrictions or global settings were changed
to bypass this boundary.

## Fresh independent review of this comparison

An independent review read the frozen tasks and rubrics before subject outputs,
then substantively inspected all six pairs. It recomputed matrix equilibria with
exact rational algebra, checked all observation source notes and session rows,
recompiled the Ink sources and replayed the delivered saves through fresh native
Story instances, and validated both glTF outputs through direct Khronos calls.
Those native checks bypassed the subject verifiers and candidate adapters.

The verdict is **PASS for the qualified diagnostic report**, retaining main's
localized prose defect and all reported experiment limits. The reviewer found
no new experiment/report correction necessary. All 235 original evidence files
still matched their manifest. The full review, scripts, actual results and
scope hashes are in [behavior-independent-review.zip](behavior-independent-review.zip)
and its [manifest](behavior-independent-review-manifest.json). A file-hash
inventory is identity evidence, not a claim of substantive review of every line.
This review does not certify packaging, licensing or native model selection.

## Acceptance boundary

[hosted qualification](README.md#fresh-native-client-lifecycle). Automatic
selection and task performance in an authenticated native installed-client
conversation remain **BLOCKED / NOT VERIFIED**. This comparison does not close
that part of full product acceptance.
