Дополнительно исправлена предметно связанная граница времени: `1 <= warning_tick <= resolve_tick <= stop_tick`, threat IDs различны. Это согласует контракт с существующим автоматическим clock, который начинает обработку на tick 1. Одновременные warning/resolve разрешены в фактическом порядке событий; новый native probe подтвердил warning перед resolution на tick 1.

После реального timeout импорта добавлен явный `--timeout-seconds` для native `run` и `suite`. Default 30 секунд сохранён; значение должно быть конечным и положительным, записывается в receipt, автоматических повторов нет. Это улучшение доступности runner при конкретных условиях запуска, а не вывод об ошибке компиляции игры.

Причины исправлялись у своих владельцев. Основная предметная база review выдержала; её не заменяли новой универсальной инструкцией. Ошибка eligibility потребовала общей исполняемой границы, ошибка измерения — семантической проверки до подсчёта, слабый oracle — достаточного следа операций, нехватка поставки — native metadata и lifecycle-инструкций. Фактическая загрузка и применение знаний моделью остались непроверенными и не «исправлялись» по догадке.

## 3. Состав и разделение ответственности

Сохранены семь полных методов: `game-design`, `gameplay-design`, `game-information-design`, `game-world-narrative-design`, `game-systems-design`, `game-participation-design`, `game-content-design`. Поддерживаемая install unit — весь bundle: sibling references и runtime resources остаются достижимыми. Прямой вход в специальность и пропуск неприменимых методов сохранены.

Предметные конструкции охватывают действие/время/пространство, создание и изменение мира и уровня, сущности и знание персонажа, сцены и последствия, ресурсы/права/восстановление, совместное участие, доступ, обучение и репертуар. Сохранены выразительная деятельность без победы, мир без обязательной симуляции, постоянная помощь, намеренный повтор и допустимое завершение. Достаточность относится к отношениям и артефактам, рассмотренным в [review, §3](review-game-design-project.md#3-фактический-содержательный-охват), а не ко всему production workflow большой игры.

В состав входят authored Harbour/gamebook и Loom, East Gate, adaptation/Lens Workshop, analysis-lab с реальной CSV/SQLite обработкой и миграцией, native Godot episode; девять игровых JSON Schemas и отдельно атрибутированная plugin schema. Maintenance tools/tests остаются вне runtime skills. Четыре client projections генерируются из `catalog.json` и `VERSION`; новый public `.agents/plugins/marketplace.json` допускается точечно, соседние private state/skills и symlink ancestors в архив не принимаются.

Game Design владеет специальными методами, игровыми артефактами и явными adapter contracts. Assay владеет общими методами исследования, разработки, проверки, review и оценки навыков. Потребитель владеет закрытым игровым контекстом, доступом к файлам, разрешениями, выбранным runtime и реальными операциями. Binder сверяет bytes выбранного owner и читает текст; он не выдаёт разрешений и не доказывает автоматическое обнаружение или исполнение метода.

Привязка обновлена штатным updater после чтения точного historical delta: семь изменённых writing-файлов сверены с прежними SHA-256 и Git blob SHA. Изменения касаются выбора уместного содержания/глубины и границ редакторской работы; имена owner, пути и интерфейс не меняются. Все 14 owner-наборов новой привязки проходят реальную проверку CLI; selected technical/text methods и conditional reference прочитаны с совпадением текста. Старый pin не считался дефектом только из-за возраста; сравнительное улучшение поведения от обновления не заявлено.

В correction применены соответствующие стадии Assay: research-driven-change и implementation-planning для перехода review → disposition → correction; code-change и software-architecture для границ; test-audit/test-writing для различающих случаев; technical-writing для согласования документации; text-writing только для авторского игрового текста; route-subagents для раздельного владения. Перед завершением перепроверены применимость и покрытие. UI-delivery и product-flow-mapping не добавлялись как обязательная процедура к локальным CLI/методическим правкам. Модельная ветвь skill-evaluation пропущена из-за отсутствия выделенного бюджета, а не заменена экспертным самоотчётом.

Первичные domain-основания и границы их переноса сохранены в review. Дополнительно прочитан [MDA, pp. 1–2](https://users.cs.northwestern.edu/~hunicke/MDA.pdf); native маршруты опираются на [Codex plugin documentation](https://developers.openai.com/plugins/build/plugins), фактический help CLI 0.159.2 и [официальный Claude CLI reference](https://code.claude.com/docs/en/plugins/cli-reference). Сторонние game-design skill-паки не открывались и не использовались как эталон или источник исправлений.

Отдельный адресный native случай подтвердил первую допустимую границу: warning и resolution на tick 1 наблюдаются в нужном порядке. Tick 0 отклоняется новым контрактом до запуска движка. Это проверка исправленной границы и известных соседних условий, не независимый перенос на новую предметную задачу.

### Клиенты и изоляция

Для исходных Python/артефактных проверок изоляция была инструкционной: owned scratch и новые output paths. Она не доказывает техническую невозможность доступа наружу. Godot использовал отдельные project и XDG directories; OS sandbox для этих запусков не утверждается.

Для попытки клиентской квалификации сначала проверена принудительная закрытая файловая граница: user/mount/PID/network namespaces, chroot, закрытые дополнительные descriptors, нулевые capabilities и no-new-privileges; внешние и посторонние контрольные файлы оставались неизменными. Рабочие клиентские profiles/config/credentials не использовались.

- Codex **0.159.2 --version** в этой границе: **exit 0**.
- `plugin marketplace list --json`: **exit 1 до чтения registry**, bootstrap требует отсутствующий `/proc/self/exe`.
- Попытка создать настоящий procfs только внутри собственных namespaces, с nosuid/nodev/noexec: **EPERM**, payload не достигнут. Host `/proc` не подставлялся; других обходов не предпринималось.
- Install, native listing семи skills, actual loading, disable, remove, update, rollback **не выполнены**. Marketplace metadata этим отказом не опровергнута. Ранее неудавшиеся isolation probes и uncaught optional interface-enumeration probe также сохранены как ошибки подготовки, не ошибки продукта.
- Claude binary и native lifecycle **не проверены**; v2.1.289 обозначает документационный интерфейс, не наблюдённый runtime.

Недоступность этих receipts оставляет принятую часть C4/U02/U18 незавершённой. Для их закрытия нужна разрешённая disposable среда с реальными клиентами и подходящим procfs; нельзя считать рабочую установку разрешённой только потому, что подготовлены команды. Windows этими Linux-проверками не квалифицирован; CI данного PR на момент записи ещё не запущен. Его последующий результат относится к конкретному head PR и должен учитываться отдельно.

### Модели и люди

Явно выделенного модельного бюджета не было: **0 behavioral baseline runs, 0 candidate runs**, средств model runner для испытаний не вызывали. Работа экспертных помощников над review/correction не считается поведением оцениваемого skill-пака. Автоматическое обнаружение, выбор, загрузка references, исполнение прочитанного метода, стоимость и независимый перенос моделью не установлены.

Не было новых playtests, наблюдений участников, аудиопрослушивания или hardware/network испытаний. Ручной разбор gamebook устанавливает согласованность заданного текста и состояний; он не доказывает агентность, понятность, удовольствие или культурную достоверность для людей.

Для повторения технических границ следует взять точный commit, установить зависимости из `requirements-dev.txt` в отдельное окружение и выполнить команды [CONTRIBUTING](../../../CONTRIBUTING.md). Native command и отдельные утверждения описаны в [Godot README](../../../examples/godot-episode/README.md); перед новым run нужен новый output path. Архивирование и smoke не являются release publication. Путь сохранённой сессии в raw argv — происхождение свидетельства, не обязательный путь на следующей машине.

## 6. Пригодность и остаток

Версия пригодна для **явного source-чтения полного набора методов и предметной работы с проверяемым артефактом**, а также для описанных Python consumers и конкретного headless Godot episode в проверенном execution vector. Прежние ошибки measurement/eligibility/reload acceptance исправлены и подтверждены различающими случаями. Это позволяет использовать версию как собственную техническую и содержательную исходную линию для последующих изменений.

Она **не объявляется полностью квалифицированной native-поставкой для Codex/Claude**. Остаются конкретные обязательные lifecycle receipts; до них продукт следует применять через явно выбранный source-route либо отдельно квалифицировать выбранный клиент. Не установлены улучшение работы моделей, качество опыта людей, полная изоляция произвольного игрового контекста, сетевой multiplayer и произвольный production pipeline миров/уровней.

Следующее изменение должно сравниваться с этим commit и относящимися к нему входами/outputs. Повтор известного контрпримера подтверждает этот случай. Для утверждения независимого переноса понадобятся новые задачи и отдельно согласованные средства/бюджет; текущая запись не выдаёт разрешения на такую кампанию. Повторный общий независимый review, выпуск релиза и установка в рабочее окружение в этот проход не входят.
